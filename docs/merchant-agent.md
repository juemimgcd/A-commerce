# 商家经营 Agent 四模块

本阶段在商家角色基础上增加经营诊断、库存补货、客户分群和固定价活动。入口为 `/merchant`，继续使用用户账号选择自己经营的店铺。代码实现与本地验证不代表生产发布。

## 功能与入口

| 工作台入口 | 已实现内容 |
| --- | --- |
| 经营诊断 | 本期/上期同快照计算；SKU 销量、净收入、部分毛利及贡献排序；退款和毛利异常；商品、活动、费用分解；保存报告和分页证据 |
| 库存与补货 | 全店 SKU 风险分页、规则版本、完整经营日销量、覆盖天数、在途抵扣、补货草稿、确认/开始/取消、原子实际收货 |
| 客户分群 | 本店支付 RFM 规则预览、固定成员快照、快照失效、首购队列的成熟观察期支付复购 |
| 活动方案 | 单 SKU 固定价测算、公开或定向快照、草稿、店主版本确认发布、停用、预算账与真实订单复盘、批准和业务失败记录 |
| 订单履约 → 订单详情 | 配送、包装、支付三类费用，实际/估算/未知、完整性声明、追加版本修订 |
| 经营助手 | 保留原 5 个工具，增加诊断、保存报告读取、库存、补货草稿、人群快照、活动测算/草稿/复盘工具；返回可信工作台资源入口 |

Agent 不能发布或停用活动，也不能确认补货、登记收货、改价格、退款或修改记忆。内部资料写入在事务中重新校验账号、店铺及运行状态，重复调用使用稳定的业务键。停止对话不撤销已提交的业务资料。

## 口径

- 期间收退款继续按资金发生时间统计；经营表现按支付订单群读取当前一致性快照。
- 金额使用整数分。成交价格已经包含活动价差，不再次扣减优惠。
- 商品成本使用订单快照；退款成功和可再售入库是不同事实，不能把申请退货的占用数量视为已经入库。
- 毛利和贡献只统计可计算明细，返回覆盖范围。未知成本、未知费用与确认为零分开。
- 贡献为同一组可计算明细的商品毛利减配送、包装和支付费用，不含运费收入。三类费用均声明完整且已确认时，才计入实际费用贡献；估算费用单列。
- 订单费用按原商品实付金额以整数分最大余数法分配，余数相同按明细 ID 排序。修订追加记录，退款不自动删除已经发生的费用。
- 保存报告保留结果与计算证据；重新计算生成新报告。`as_of` 是本次读取时点，不支持任意过去时点重建。
- 库存使用 `on_hand - reserved - allocated`。补货测算剔除未履约取消及实际验收退货；它与支付销量单列，不能当作精确需求预测。
- 支付新老客和支付复购保留支付事实，退款不抹去购买次数。复购分母排除观察期未满客户。
- 人群快照只基于本店交易，成员不返回模型，不读取全局客服记忆、不改变共享/营销设置、不发送营销信息。

## 活动交易

商家活动通过 `FlashSale.merchant_promotion_id` 关联既有秒杀，复用报价、订单、库存和支付入口。一份报价、一张订单仍只属于一家店铺。

店主确认时后端固定活动版本、参考价、成本版本、费用假设、人群、预算、限量、时间与批准摘要。首版不能原地修改已发布商业条件；需先停止未来优惠，再创建新草稿确认。

| 事件 | 预算和活动件数 |
| --- | --- |
| 报价 | 不占用 |
| 下单 | 与库存、订单、幂等及 Outbox 同事务预占 |
| 正常付款可履约 | 预占转为已消耗 |
| 取消请求/超时，支付终态未确认 | 继续保留预占 |
| 确认未付款关闭 | 释放预占 |
| 正常已付后取消或退款 | 已消耗不回补，退款和净让利在复盘单列 |
| 迟到付款导致取消补偿 | 不恢复履约；未释放的预占释放一次，不计为正常活动兑换 |

旧平台秒杀没有商家活动关联，保留原取消回补规则。新活动的 `claimed` 包括仍预占与累计正常消耗的件数。并发由同一 PostgreSQL 行锁及余额约束控制，不依赖 Redis 作为预算账本。

普通价/成本版本变化、商品不可售或快照失效后，旧活动不再接受新优惠订单。店主需要重新测算确认。已创建订单仍按原金额与支付期限处理。

公开秒杀列表和详情不返回定向活动。登录买家使用 `/api/v1/customer/eligible-flash-sales` 及其详情入口查询符合资格的活动，报价和下单再次校验。旧平台编辑入口不能修改受批准版本保护的商家活动；平台可用专用停用接口并提供原因。

## API

商家接口以下均位于 `/api/v1/merchant/shops/{shop_id}`，通过店主关系授权：

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/operations/capabilities` | 当前发布开关 |
| POST / GET | `/diagnostics` | 生成报告 / 游标列出已保存报告 |
| GET | `/diagnostics/{id}`、`/{id}/evidence` | 分页报告与证据 |
| GET / POST | `/orders/{id}/expenses` | 最新费用版本 / 追加修订 |
| GET | `/inventory-risks` | 全店风险，支持 SKU 或偏移分页 |
| PUT | `/restock-rules/{sku_id}` | 版本化补货规则 |
| GET / POST | `/restock-tasks` | 任务列表 / 草稿 |
| GET | `/restock-tasks/{id}` | 任务详情 |
| POST | `/restock-tasks/{id}/{confirm,start,receive,cancel}` | 店主确认和实际处理 |
| POST | `/segments/preview` | RFM 聚合预览 |
| GET / POST | `/segments` | 快照列表 / 保存固定成员 |
| POST | `/segments/{id}/deactivate` | 停止新定向资格 |
| POST | `/repeat-purchase` | 首购队列，默认 30 天观察期 |
| POST | `/promotions/simulate` | 固定价和销量情景 |
| GET / POST | `/promotions` | 列表 / 草稿 |
| GET | `/promotions/{id}`、`/{id}/validation`、`/{id}/report` | 版本、核验及复盘 |
| POST | `/promotions/{id}/{publish,stop}` | 店主明确确认后执行 |

平台紧急停用：`POST /api/v1/admin/shops/{shop_id}/promotions/{id}/stop`，需要 `catalog` 权限、`expected_version`、`reason` 和幂等键。

草稿、费用、收货、确认、发布及停用写入要求 `Idempotency-Key`。同键不同参数返回冲突，结果未知时使用原键重试或先读取业务对象。列表支持稳定游标或偏移，Agent 返回有下一页时不能把当前页当作全店结果。

## 迁移与启用

迁移链新增 `0009_merchants → 0010_merchant_ops`；旧活动关联和旧订单活动版本保持空。迁移不进行猜测性费用/历史成本回填，也不提供破坏性降级。

```sh
PYTHONPATH=src uv run --no-sync alembic upgrade head
PYTHONPATH=src uv run --no-sync alembic check
```

`COMMERCE_MERCHANT_PROMOTIONS_ENABLED` 默认 `false`。报告、补货和分群可使用，活动仍可测算和保存草稿。正式发布时，先备份并核验目标数据，完成迁移，同步更新所有 API、回调、worker 和 adapter，确认旧程序不再处理新活动订单后，再设置为 `true`。就绪探针要求 `0010_merchant_ops`。

关闭开关会阻止新商家活动报价/下单/发布，已有订单付款、关闭和退款继续处理。不要停掉回调或直接回滚已产生支付事实的数据结构。

## 提交前复核

- 报告、人群快照在 `REPEATABLE READ` 下等待账号锁不会更新读取快照。并发同键写入若遇到幂等唯一约束或序列化冲突，整体回滚后最多重新执行两次；新事务重新授权、校验运行状态并读取已提交结果。其他约束错误不重放。
- 平台紧急停用锁定实际管理员账号，保证同一管理员的并发同键请求正常重放。
- 部分收货后将任务总量改为已收数量，任务进入已完成状态；不追加收货、不修改实物库存。
- 工作台收货操作发生网络中断或服务端失败时，保留原幂等键和请求参数，明确重试原请求；后台刷新版本不会把重试变成新收货。保存报告列表支持游标翻页，直接打开未在当前列表页的报告也会保留选中项。

复核后的独立服务回归为 **58 项通过、2 项条件跳过**，记录在 `var/validation/commerce-test-20261030t135847z-14a049/`。后端 `scripts/check.sh`、前端及适配器 `npm run check`、空库迁移和 `alembic check` 通过；未新增或修改测试文件。
