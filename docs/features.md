# 功能清单与成熟度目标

状态：功能验收清单；后端首版已实现，逐项证据与未完成项见 [实施记录](backend-implementation.md)。v0.1 是内部联调里程碑；v1.0 是以 1 万并发在线用户为容量目标的单店后端。Agent 单独放到 M7，不是后端发布前置条件。模拟提供方、真实沙箱、生产商户接入分别记录，不能合并成一个“支付已完成”。

## 1. 使用者与边界

- 买家：浏览商品、维护购物车/地址、确认购买、支付、查看履约和发起售后。
- 运营：管理商品与库存、发货、审核退货、查询报表；按角色授权。
- pi（M7）：代表一个已授权买家，理解需求并调用受限工具；不拥有商家管理权限。
- 运维：部署、查看指标/故障任务、恢复数据、处理对账异常；关键人工操作留审计。

v1.0 单商家、单仓、CNY、数码配件实物商品。支持多用户和多设备会话，普通用户可独立完成交易。完整前端不是后端验收的前提；真实沙箱与生产接入按实际状态单独标注。容量按 [capacity-plan.md](capacity-plan.md) 验收。

## 3. 六条必须能演示的完整业务路径

### 3.1 正常购买

买家登录 → 选品/购物车 → 后端报价 → 用户确认 → 创建订单并预留库存 → 获得支付入口 → 用户支付 → 验证回调/主动核对 → 订单已支付 → 发货 → 签收。

完成依据：订单、资金记录、预留/分配库存和发货库存流水一致，API 返回与实际状态一致。

### 3.2 约束变化

买家按预算/规格筛选 → 查看价格与配送说明 → 获取报价 → 确认后价格或地址改变 → 后端拒绝旧报价 → 新报价与新确认。

不能自动替换到更贵商品，不能把“预计送达”说成保证送达。

### 3.3 放弃支付与延迟成功

未付款订单到期 → 后端尝试关闭支付 → 核对结果 → 释放库存并关单；若出现延迟扣款，则进入唯一补偿退款，不能同时正常履约和退款。

提供方不可用时展示 closing/unknown，生成告警和人工处理记录。

### 3.4 已支付取消

用户确认取消 → 后端竞争校验未进入拣货/发货 → 取消并释放分配库存 → 持久化退款操作 → worker 执行 → 回调/查询确认退款。

发货若先成功则取消失败并解释当前可执行的售后路径。

### 3.5 部分退货

用户选订单行和数量 → 后端计算可退数量/金额 → 确认申请 → 寄回与收件 → 管理员验收 → 可再次销售部分入库 → 唯一退款操作 → 更新退款累计。

当前有效退货数量与已完成退货数量不能超过已购数量。并发申请通过订单行锁和约束处理。运费退还遵循快照政策，不随每次部分退款重复退。

### 3.6 订单通知与恢复

用户保存通知偏好 → 物流异常产生事件 → 生成站内通知/邮件任务 → 用户读取通知和订单状态 → 连接中断后按游标恢复。

重复事件不重复发通知，游标过期有快照恢复方式。M7 的 pi 可以消费这些业务事件；自动唤醒模型与 Agent 授权另行实现和验收。

## 4. 业务规则必须可解释

- 报价：10 分钟；订单待支付：15 分钟，均可配置。调度晚到不改变数据库中的有效期判断。
- 售后：演示规则为签收 7 天内可申请；规则有版本，按订单快照计算，支持管理员记录拒绝原因。
- 退款：退款和待处理退款占用余额共同受限；同一订单支持多次部分退款，累计不得超实付。运费只按规则退一次。
- 商品和地址：下单保存快照，后续编辑不改历史；商品下架不能删除历史订单关联。
- 删除与保留：商品归档、账号停用；订单、资金和审计不直接物理删除。账号删除/匿名化按已确定的保留政策执行，不提供一键级联删除交易历史。
- 取消边界：paid 且未进入 fulfilling 可取消；进入拣货后需人工处理或到货退货，不能通过直接改状态越过流程。

这些是产品设计规则，不是法律/平台政策的替代。

## 5. 运营数据定义

销售额按已确认支付统计；退款按已确认成功统计；净收款为收款减退款，不称利润。分别保留支付时间、退款时间和订单创建时间，报表展示采用哪种口径。

商品销量、退货率、未支付关闭数量、库存占用时间、退款待处理时长采用真实记录计算；没有数据时返回明确空结果，不生成示例成绩。报表读取增量汇总，导出异步执行、限制时间范围并防止 CSV 公式内容被执行；M7 再补 Agent 指标。

## 6. 成熟度验收门槛

| 方面 | v1.0 的验收要求 |
|---|---|
| 可重复部署 | 空 PostgreSQL 迁移成功；冻结依赖安装；幂等初始化；不在多副本启动时重复迁移 |
| 交易正确性 | 最后一件并发购买无超卖；多 SKU 任一失败全部回滚；重复下单/回调/退款无重复副作用 |
| 故障恢复 | 在外部成功、本地提交前后分别停止 worker，重启后可核对；RabbitMQ 确认丢失/断连/重复投递可恢复，未完成操作从数据库补发；非法消息隔离且不无限重试 |
| 权限 | 多用户对象隔离；管理员权限划分；会话撤销/账号禁用生效；买家不能访问管理/提供方接口 |
| 数据安全 | 日志脱敏；凭证摘要；密码哈希；受限上传；回调验签；输入大小/速率上限 |
| 可观测 | HTTP 错误/延迟、池等待、SQL/锁等待、缓存命中、发布确认/退回、ready/unacked/重投/隔离队列、业务任务完成率、outbox 最老年龄、未知资金操作与对账差异有指标和告警；覆盖所有进程 |
| 数据恢复 | 备份可恢复到隔离数据库；记录恢复时间与校验结果；不只确认“备份文件存在” |
| 性能证据 | 按容量计划完成 1 万活跃用户与到达率验证，记录实际 RPS/成功下单 TPS、p50/p95/p99、失败、资源和积压；故障恢复后核对业务一致性 |
| 交付证据 | 功能、代码、验证记录对应；模拟/沙箱/生产连接状态分别标注 |

已完成部分手工联调，具体证据见实施记录；此处全部门槛尚未验收完成。自动化验证代码需在用户明确授权测试实施时创建。

## 7. 后续版本

M7 优先接入 pi：选品/报价工具、grant 范围/额度/有效期/撤销、action 独立确认与执行、部分售后工具、事件恢复。普通用户接口保持独立可用；Agent 不得自批、模拟支付或访问管理接口。固定模型/提示词/工具/数据版本，记录成功率、约束违例、耗时、成本与最终业务状态。

后续产品能力：换货、优惠券和促销（需新增价格分摊/优惠释放/退款规则）、价格监控、浏览历史与可控偏好、多渠道通知、完整 Web 管理与确认界面、MCP 适配。

更后：多仓拆单、多个商家、真实生产支付、平台分账、供应链采购、复杂推荐。每项根据业务需求引入，不以框架/中间件数量作为成熟度标准。
