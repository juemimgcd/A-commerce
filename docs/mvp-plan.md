# 分阶段实施与发布门槛

状态：分阶段验收计划；首版实现与验证进展见 [实施记录](backend-implementation.md)。先交付成熟后端，以 1 万并发在线用户为容量目标，Agent 延后到 M7。保留完整交易状态；消息采用 RabbitMQ + aio-pika 异步 worker，PostgreSQL 保存可恢复的业务状态，Redis 只承担缓存和限流。

总架构见 [architecture.md](architecture.md)，完整功能见 [features.md](features.md)，负载和服务目标见 [capacity-plan.md](capacity-plan.md)。本文只确定顺序与阶段完成依据，不创建测试代码或演示脚手架。

## M1：工程、身份、权限与资源预算

交付：

- 按新闻项目习惯建立 routers/services/crud/models/schemas/conf/cache。
- FastAPI app factory、lifespan、配置校验、统一错误、请求 ID、结构化日志。
- PostgreSQL/Alembic，首次迁移与管理员初始化，根目录环境示例。
- 用户注册/登录/退出、地址、staff 权限与可撤销服务端会话。
- API 无状态；DB/Redis/HTTPX 有界连接池、统一超时、入口限流、指标采集与进程汇总。
- API、migrate、数据库、Redis cache、RabbitMQ 的开发 Compose；MQ 的 vhost/账号、连接超时/心跳、版本化拓扑与隔离队列策略；不启动尚未实现的应用服务。

完成依据：空库迁移成功；重复初始化不覆盖业务数据；两个买家和不同 staff 权限隔离；会话撤销生效；环境缺配置时给出清楚错误；MQ 拓扑可重复声明且权限明确；能计算所有进程和发布重叠期的 DB/AMQP 连接上限。

工程代码、冻结安装、静态检查和本机身份/服务联调已有记录；各项完成依据仍按实施记录逐项核实，不能以依赖解析成功替代阶段验收。

## M2：商品、购物车、报价与高频读路径

交付：

- 分类、SPU/SKU、规格、价格与上下架、管理员库存调整。
- 可解释搜索、分页、比较字段；少量商品用于功能联调，正式容量数据规模另按容量计划准备。
- 购物车、地址、固定运费、报价有效期与快照。
- Redis 热点读缓存、TTL 抖动、请求合并、有限回源；交易报价直接核对数据库。
- 稳定分页、查询上限、复合索引、避免 N+1；公开浏览不查询用户会话。

完成依据：API 可完整支持选品/购物车/报价；金额、数量、有效期和地址受后端校验；冷热读路径、SQL 数量、缓存命中与池等待可观测。

这时开始分级容量评估，先定位查询与缓存瓶颈；不等到 M6 才第一次观察性能。压测脚本与数据生成在相应实施请求授权后创建。

## M3：确认、订单、库存预留与异步支付

交付：

- 用户确认报价后直接通过 customer/orders 下单；报价过期/变化拒绝、稳定幂等键与结果查询。
- 创建待支付订单、预留库存、幂等记录、payment_intent 与 outbox 原子写入。
- 原生 asyncio worker：进程级事件循环和连接池、消息 schema/处理映射、prefetch 与总并发限制、手动 ack、robust 重连和优雅退出。
- outbox relay：持久消息、mandatory 路由检查、publisher confirms、发送租约和重复发布恢复。
- 数据库驱动的 next_attempt_at 重试、执行租约/fence、失败/未知操作核对、毒消息隔离、到期扫描与独立模拟支付提供方。
- 支付入口、签名回调、主动查询、关闭支付、结果未知核对。
- 关键支付与通用任务划分队列和并发预算；订单状态查询。

完成依据：

- 同一报价/幂等请求不重复下单；两人购买最后一件只有一个预留成功。
- 多 SKU 部分缺货整单回滚；确认后改价/地址变化要求重新确认。
- 用户完成模拟支付后才显示已支付；超时不能当成成功或失败。
- 到期关单与支付成功竞态、迟到回调都有确定结果，无超卖或无记录收款。
- 客户端/网络中断后可通过幂等结果和订单查询恢复；订单成功以事务提交为准。
- 发布确认丢失、处理提交后 ack 丢失、worker/连接中断均可恢复；重复消息不重复执行副作用，不可路由消息不能标记已发送。
- 业务重试先保存计划再确认原消息，不无限立即重入队；非法消息进入隔离处理，数据库故障时不提前 ack。
- 混合读写与热点 SKU 分别记录，支付后台产生率、完成率和积压年龄可观测。

完成后标记 v0.1 内部联调可用，明确外部支付仍为模拟。

## M4：履约、取消、退货退款

交付：

- 拣货/发货/签收及模拟物流事件。
- 未发货取消、库存释放、全额退款。
- 先整单退货，再按行/数量部分退货、收件验收、可售库存恢复。
- 退款占用余额、稳定提供方操作 ID、unknown 核对、资金对账与人工处理。

完成依据：取消与发货并发不产生双成功；重复验收不重复入库；并发退款总额不超实付；实际退款结果与财务/订单展示一致；原订单履约历史仍可追溯。

按真实沙箱适配要求接入一个提供方需要可用账号/凭证。尚无凭证时继续完成模拟与内部验证，真实沙箱一栏保持未接入，不以模拟成绩替代。

## M5：运营与用户持续使用

交付：

- 商品图片、受限上传、本地/S3 存储适配、导入错误报告。
- 购物收藏、运费模板、管理员搜索与权限细分。
- 多设备会话、邮件重置密码、改密/禁用撤销会话。
- 站内通知、邮件通知、用户偏好、事件游标与过期恢复。
- 销售、退款、净收款、商品排行、库存告警、异常任务与脱敏导出。
- 报表增量汇总、导出单独消费、事件投影与积压处理；失败/隔离消息查询、业务核对后人工重放与审计。

完成依据：运营能独立维护目录/库存/履约/售后；统计来自真实已确认数据；邮件/S3 按环境明确启用状态；重连不漏事件，重复事件不重复触发同一任务；慢报表不挤占交易任务。

## M6：1 万在线用户、故障恢复与后端发布

交付：

- CI 的冻结安装、格式/类型检查、数据库迁移验证与依赖审计。
- 关键业务、并发、回调乱序与故障恢复验证；自动化代码须在相应实施请求明确授权后创建。
- RabbitMQ 重启/断连、发布与消费确认边界、队列容量/死信目标故障和 DB 重试恢复；采用三节点高可用部署时额外验证 quorum 故障，单节点结果不冒充高可用。
- 独立压测端、目标数据规模、真实路径比例与思考时间，逐级升到 1 万活跃用户。
- 30 分钟稳定运行与 2 小时持续运行；另外验证到达率、热点、冷缓存、集中登录、故障和滚动发布。
- 记录实际 RPS/成功订单 TPS、p50/p95/p99、错误、池/锁等待、资源和队列积压；故障后继续核对资金与库存。
- 日志、指标、OTel 可选导出、告警和全部进程指标汇总；覆盖 RabbitMQ ready/unacked、发布确认/退回、重投、隔离队列、磁盘/内存与连接状态。
- Compose 部署、单次 migrate job、非 root 镜像、优雅退出、网关与访问边界。
- 数据库备份恢复演练、消息补发、支付/退款差异与人工恢复手册。

v1.0 发布条件：features.md 的 v1.0 功能列、成熟度门槛和 capacity-plan.md 的目标有逐项证据，未启用的外部集成单独标记。不得用 Docker 启动成功、类型检查、空闲连接数或一次正常交易替代发布验收。

## M7：后端验收后再接入 pi

交付：独立 TypeScript 适配器、只读工具、Agent grant、可信 action 批准与执行、调用结果恢复、事件同步；按用户明确授权实现可选事件跟进。

顺序：先验证商品/报价查询，再增加批准后的下单/取消/售后工具。Agent 调用已有 service，不重写库存/支付规则；普通用户下单继续独立运行。

完成依据：固定场景、模型、提示词、工具与数据版本，核对约束、工具轨迹和最终数据库状态；grant 撤销生效，Agent 不可自批或访问管理/提供方接口。记录 pi/模型端到端验证，不能替代 M6 的后端容量证据。

## 统一验收记录格式

每项保留：功能/场景、代码版本、依赖锁版本、环境、数据库/模拟提供方初始状态、执行方式、预期与实际业务状态、失败证据、是否复现与修复、外部服务类型。

M7 额外保留：模型、提示词、工具 schema 版本、输入约束、工具轨迹、最终数据库状态、调用数、耗时、token/成本。隐藏推理不是验收数据；日志中的私人信息需脱敏。

业务验收优先覆盖：缺货、变价、报价过期、重复执行、用户隔离、支付超时、迟到回调、发货竞争、部分退货、退款核对、进程重启；容量验收另按容量计划记录。

覆盖率和性能不预先写成绩。每阶段报告“已实现 / 已静态检查 / 已集成验证 / 已模型端到端验证 / 已部署”的实际状态。
