# 卖家经营概览

`/merchant` 默认进入经营概览；已有 `tab=products/orders/reports/...` 链接继续可用。浅蓝灰、白色面板、蓝色主指标的视觉仅作用于卖家工作台。商城与平台管理仍使用原来的外壳。

## 内容与口径

- 默认近 7 个上海经营日，包含今天；支持今天、近 30 天及自定义 1–366 天。界面结束日期包含当天，API 的 `end` 不包含。
- 刷新或失败重试时，今天/近 7 天/近 30 天按当前上海日期重新计算，自定义区间保持原值。点击左上角品牌返回当前店铺的概览。
- 商品净收入按期间支付订单群统计，减截至查询时点成功的商品退款，排除运费。与现有经营报表一致；历史退款分配缺失时返回 `null`，不按零展示。
- 支付订单数保留支付事实；新增客户按本店首次支付日期去重。
- 退款金额按退款成功发生日期统计，包含运费退款，可以来自往期订单。
- 本期、上一等长周期和逐日数据来自同一个主库只读、可重复读事务。上期为零或金额未知时不显示增长百分比。今天与完整上期的对比标明今天仍在累计。
- 经营待办不受日期筛选影响：待发货为已付款且待拣货/拣货中；售后为待审核、已寄回或待验收；待确认补货为草稿。
- 低库存仅统计在售商品的在售 SKU：可售库存 `on_hand - reserved - allocated` 不高于已配置 `low_stock`；未配置规则时只统计缺货。另列未配置 SKU 数量。它不是完整库存风险模型中的销量覆盖天数预警。
- 最近订单独立读取全店最新 5 笔，可打开原有订单详情。支付结果已关闭时显示“未付款”，准备中/处理中/未知及未识别的结果显示“实付待确认”，并单列订单金额；已付款或已退款订单显示原实付金额。
- 经营助手入口携带当前店铺和日期，预填分析问题，不自动发送。

## 接口

`GET /api/v1/merchant/shops/{shop_id}/overview?start=YYYY-MM-DD&end=YYYY-MM-DD`

返回 `current`、`previous`、`days`、`todos`、`as_of` 和日期范围。通过原有用户会话及店主关系授权；前端代理只放行 GET。无写操作、无新迁移、无新增依赖。

## 本地验证

- 后端格式、Ruff、mypy、编译检查及前端格式、ESLint、TypeScript 检查。
- 在独立复制的本地 PostgreSQL 数据库中查询本期/上期/空期间，对照原有经营报表的四项指标；非法日期区间返回 422，非店主访问返回 404。
- 桌面 Chrome 验证日期切换、空状态、未知金额、趋势切换、每日明细、订单详情及经营待办入口。
- 提交前复核：后端及前端静态检查通过；独立 PostgreSQL、Redis、RabbitMQ 环境的空库迁移、模型一致性及现有回归通过（58 项通过，2 项条件跳过），记录位于 `var/validation/commerce-test-20261031t112427z-1b8bae/`。现有回归不专门覆盖全部新增汇总组合；未知支付及跨午夜分支完成代码复核，未做支付故障或时间注入。
- 未新增或修改测试。没有生产发布；本地历史数据不代表生产经营情况。
