## 后端补齐

没有新增数据库迁移。展示接口继续检查现有身份与权限，不另建订单或付款状态机。

- 商品输出批量提供封面引用；购物车包含商品 ID、规格属性和封面。
- 报价增加规格快照，并提供仅所属买家可读的报价查询。
- 增加买家/管理员自身资料、权限与当前会话标记。
- 增加受 `catalog` 权限保护的商品详情、草稿媒体预览、分页库存与单规格库存、运费规则读取。
- 售后详情包含申请行、数量、成交金额、时间、退款结果和配置的寄回地址；订单提供政策快照及退货截止时间。
- 公开商店能力说明用于判断模拟支付、邮件、正式政策和寄回地址是否可用。

新增接口见 `routers/storefront.py`，查询见 `services/storefront.py`；契约导出到 `frontend/openapi.json` 并生成 TypeScript 类型。

## 交易与恢复行为

浏览器持有 HttpOnly 会话 Cookie；原始后端 Token 不返回给浏览器代码，也不写入本地存储。买家与员工会话分开。写请求校验来源，转发只开放明确的方法与路径，并限制上传大小。

下单前保存账号、报价 ID 和稳定请求编号。网络结果未知时先查询原请求；刷新仍可恢复，单次未查到不触发换键下单。退货和库存调整也保留未决请求。交易写入不自动重试，离线时不会在恢复网络后静默排队提交。后端报价和订单响应经过关键字段校验，金额始终使用整数分。

支付/订单与导出查询只在可见且联网时有界轮询，自动等待最多两分钟；停止等待保留当前未知状态和手动刷新。服务端 `Retry-After` 控制同一操作的再次发送。取消和履约携带当前订单版本，冲突后读取最新状态。

敏感操作超过最近认证期限时，在弹窗内重新验证身份，保留原确认步骤，由使用者再次提交。实物“已验收”与资金“已成功”分别显示。成交后购物车保留原行，用户手动移除，避免自动清空其他标签页修改的商品。

业务时间显示北京时间；资金日报与排行遵循后端已有的 UTC 自然日口径，并在页面和 CSV 中明确标注。UTC 当日对应北京时间当日 08:00 至次日 08:00。

## 运行与发布边界

运行命令、环境变量和容器入口见 [frontend/README.md](../frontend/README.md)。本机当前使用模拟支付/物流，邮件默认关闭。正式商家联系方式、退货地址、隐私与条款仍需商家提供并配置；缺失时界面显示相应说明。

本次没有生产发布、真实商户支付沙箱、真实 SMTP/S3 或 1 万在线容量结论。网关读取与 IP 验证使用实际容器；完整容器交易切换需先迁移同一份提供方与媒体数据。密码更改、不同权限账号的全部界面组合和真实移动设备触屏/输入法仍需进一步专项验收。
