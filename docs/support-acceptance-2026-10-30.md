## 修复

1. **商品查空误判**：模型曾把“AHC护肤套装”整体当作标题子串，漏掉实际有货商品，并猜测品牌价格超过预算。明确 q 的子串语义、品牌字段和查空后的关键词收敛策略；复查必须保留用户约束。
2. **商品入口与最终推荐一致**：整轮保留成功查询过的商品，模型通过 `commerce_respond` 的 `product_ids` 选择最终介绍的商品。后端核验每个 ID 来自本轮成功查询，使用业务工具产生的标题与 URL，并去掉未选择的商品入口。支持跨品牌比较、跨页选择及收窄筛选；订单等其他业务入口保留。不会仅凭最后一次搜索替换全部商品入口。
3. **时间和售后说明**：补入当前可信时间，要求按 Asia/Shanghai 展示，不直接把 UTC 原值当本地时间；明确付款不等于可申请退货，数量以资格工具为准。
4. **记忆授权说明**：明确使用长期记忆不需要共享画像或启用营销，避免模型将多个开关混在启用建议中。
5. **回复与观测**：约束模型输出纯文本以适应现有页面，新增结构化运行指标。指标日志不保存用户原文、工具参数、完整回复或 token；这里的 token 指认证凭证，计量 token 数仍记录。

## 运行与检查

`pi-adapter` 支持 Node >=22.19.0。Python API 需要根目录 `.env` 的数据库、Redis 等现有设置和 `COMMERCE_SUPPORT_BRIDGE_SECRET`；Node 适配器从进程环境读取变量，不自动载入根目录 `.env`。

两端注入同一个至少 32 字符的随机 bridge secret；API 端设置 `COMMERCE_SUPPORT_ADAPTER_URL`，Node 端设置可回连的 `COMMERCE_API_ORIGIN`。模型默认读取 `~/.pi/agent/settings.json`、`auth.json` 和可选 `models.json`；可通过 `COMMERCE_PI_AGENT_DIR` 指向专用配置目录，或通过 `COMMERCE_PI_PROVIDER`、`COMMERCE_PI_MODEL`、`COMMERCE_PI_API_KEY` 指定配置。不要将凭证放入模型消息或提交到 Git。

数据库先运行 `uv run --no-sync alembic upgrade head`（当前 `0006_support`），API 使用现有 Uvicorn 工厂启动方式；适配器在 `pi-adapter/` 执行 `npm start`。适配器默认绑定 `127.0.0.1:58010`，没有外部入口；容器网络地址需在部署时明确配置。`/health` 只表示运行时初始化成功，不保证提供方后续请求成功。

## 审核修复复查

同日审核发现，按每次搜索清空商品入口会误删多品牌比较和翻页后仍被选中的商品；工具轨迹只在收到 HTTP 响应后追加，会漏掉连接失败。已按上述最终商品选择契约修复入口，并为工具执行记录 `status`（无响应时为 null）、`outcome` 和 `duration_ms`。执行结果区分成功、网络错误、超时、取消、HTTP 错误、JSON 解析失败、响应结构不符、结果过大及预算/参数错误，不记录原始异常、参数或凭证。

新增原始记录为 `review-fixes-2026-10-30.jsonl`、`review-adapter-2026-10-30.log`、`review-network-2026-10-30.log` 和 `review-network-results-2026-10-30.jsonl`。实际真实模型复查结果：

- 两品牌各选最便宜的一件：保留 AHC 96.90 元和欧莱雅 60.72 元两个入口。
- 先查第一页再翻第二页，各选一件：保留第一页芙丽芳丝和第二页 Whoo 两个入口。
- 从 200 元内商品收窄到 100 元内 AHC：只保留 AHC 入口。
- 1 元以内 AHC 查空：回复无结果，商品入口为空。
- 回连未监听端口：日志为 `status=null/outcome=network_error`，模型告知查询失败。
- 无效运行能力凭证：实际后端返回 401，日志为 `status=401/outcome=http_error`。
