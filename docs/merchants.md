# 商家角色实施与发布

依据 [最终纲要](merchant-plan.md) 实施。本文记录接口、迁移与本地验证结果；不代表已发布到生产。

## 入口与权限

- `/merchant`：用户账号登录，选择自己经营的店铺；提供商品、SKU、成本、库存、图片、履约、售后、统计和只读经营助手。
- `/admin/shops`：平台员工使用 `identity` 权限创建店铺、维护资料、调整状态。创建时填写已注册店主的邮箱；新店初始暂停，资料齐备后显式启用。
- 店铺可一人多店；平台员工与用户身份、会话保持独立。
- 商家前端查询缓存隶属于用户身份缓存，退出、换账号时清除；店铺及会话切换使用不同的查询键。

API 前缀为 `/api/v1/merchant/shops/{shop_id}`。所有读取与写入都在服务层验证店铺归属，路径中的店铺编号本身不授予权限。商品及成本写入使用各自版本号；库存调整使用 `Idempotency-Key`。

平台的 `/api/v1/admin/shops/{shop_id}/products`、`/reports` 以及 `/skus/{sku_id}/cost` 继续按 `catalog` 或 `audit` 验证具体权限。商家不能通过这些路径获得平台权限。

## 交易与统计

购物车按店铺分别结算。一份报价、订单与支付意图只属于一家店；混店请求整体拒绝。店铺暂停后不再接受新报价或下单，已有待支付订单可继续完成付款或关闭，已有售后可继续处理。

关闭店铺前，已签收订单也必须超过成交政策快照中的售后期限。退货申请与关闭操作统一先锁店铺、再锁订单；申请提交后，未完成售后会继续阻止关闭。已关闭店铺拒绝新增退货申请，已有申请的幂等重放仍可查询原结果。

单位成本在创建订单时固定，单独改成本不会改变商品报价版本。品类、原价和成本保存成交快照，公开商品与报价输出不返回成本。

退款写入原成交明细分配及运费部分，退货验收记录可再售结果和时间。沿用已有订单锁、退款余额预占、库存流水、Outbox 和 worker 幂等处理。

`GET /reports?start=YYYY-MM-DD&end=YYYY-MM-DD` 的结束日期不包含在内，区间最长 366 天。主库使用同一只读、可重复读事务：

- `cash`：支付及退款分别按各自发生时间计入期间；运费单列。
- `performance` 与 `products`：期间支付订单截至查询快照时点的商品净收入、成本、毛利与覆盖率。
- `customers`：本店去重购买人数、新老客、购买频次、成交品类、收货地区与消费分布。
- 未知成本不当作零；历史退款分配未知时，不声称商品净收入或毛利完整。
- 商品毛利排除运费、税费、手续费，与净收款、净利润和可提现余额含义不同。

## 经营 Agent

复用现有 pi adapter 与运行协调，不修改 pi 核心。商家会话和运行持久化绑定 `shop_id`，买家客服入口不能读出商家会话。能力凭证仍受用户会话、超时、取消和每轮 12 次工具预算约束。

商家运行使用独立提示词及以下工具：

- `get_shop_sales_summary`
- `get_product_sales`
- `get_shop_customer_statistics`
- `list_shop_orders`
- `list_shop_products`

不注册买家工具、记忆提议工具或任何经营写工具。订单工具排除地址、联系方式、买家标识与政策快照；原始客服记忆不作为商家数据来源。

接入使用原有 `COMMERCE_SUPPORT_*` 后端配置及 pi adapter 的模型配置。未配置模型桥接时，经营后台仍可使用，咨询接口明确返回未配置状态。

## 迁移与历史自营店铺

迁移链：`0008_flash_sales` → `0009_merchants`。`0008_flash_sales` 已通过独立 PR 合并到 `main`；本次商家扩展基于该版本继续迁移。

`0009_merchants` 新增店铺、商品及订单归属、成本与品类快照、退款分配、验收结果、媒体上传人及商家会话字段。既有数据归入“历史自营店铺”，历史成本与无法证明的快照保持未知；旧报价失效。保留账号禁用且没有有效密码，历史店铺初始暂停。

执行正式迁移前，必须按纲要安排写入切换窗口，核对备份、资金、退款、库存及版本。命令如下，均使用目标环境原有配置：

```sh
PYTHONPATH=src uv run --no-sync alembic upgrade head
PYTHONPATH=src uv run --no-sync alembic check
```

历史自营店铺首次配置：

1. 通过普通用户注册创建并核验专用店主账号。
2. 执行下列命令，仅允许首次绑定，不修改密码，也不启用店铺。
3. 平台在店铺管理中补齐退货地址，核对原数据后显式启用。

```sh
PYTHONPATH=src uv run --no-sync python scripts/configure_legacy_shop.py OWNER_EMAIL
```

需要保留有效历史订单的退货地址时，应在切换前确认原部署的退货地址配置。旧订单缺少专属快照时继续使用该原配置，新订单保存店铺地址快照。

同步发布 API、worker、relay 和 adapter，更新公开商品缓存与搜索内容，避免长期混跑新旧写入程序。模型及权限不使用读副本。`/health/ready` 要求 `0009_merchants`。

迁移不提供破坏性降级。新商家订单产生后使用前向修复；发生外部支付后不得仅恢复旧数据库备份并忽略提供方资金事实。

## 本地验证记录

环境为本机独立 Docker 项目的 PostgreSQL、Redis、RabbitMQ，独立模拟支付服务、API、relay 和 worker，未连接业务数据库或真实支付提供方。浏览器使用独立前端预览目录，没有停止原有前端开发服务。

已验证：

- 空库执行全部迁移，`alembic check` 与模型一致。
- 平台创建店铺，店主拥有多店，另一店主无法读取本店商品与订单。
- 商品、SKU、库存、成本、买家地址、单店报价和下单；混店请求返回 `CROSS_SHOP_CHECKOUT`。
- 公开 SKU 输出不含成本；购物车返回店铺归属与名称。
- 重复下单返回同一订单；库存调整不能扣除已占用数量。
- 暂停店铺后拒绝新报价，已有订单仍可付款；未处理完订单时不能关闭。
- 100 元商品、60 元成本，支付后商品毛利 40 元；可再售退货、退款完成后商品净收入与成本均为零，运费仍单列。
- 重复验收不重复入库；未发货取消退款的收入与成本冲回。
- 下单后把当前成本从 60 元改成 70 元，原订单两件商品仍按 120 元成本统计。
- 成本未知时毛利返回未知，成本覆盖率为零。
- 商家 Agent 工具读取与后台相同结果；跨店商品拒绝、买家工具拒绝、买家客服入口无法读取商家会话；取消运行后凭证失效。
- 390、768、1440 像素浏览器检查，手机表单按整行排列，数据表格在自身容器横向滚动。
- 后端静态检查、前端检查、pi adapter 类型检查，以及现有存储契约测试。

审核修复时复现了测试夹具清空店铺后插入商品的外键错误；经授权，在 `tests/conftest.py` 重建有效的默认测试店铺，未新增或修改测试用例。独立临时 PostgreSQL、Redis、RabbitMQ 环境重新执行空库迁移、`alembic check` 与完整现有回归，58 项通过、2 项按环境条件跳过。运行记录位于 `var/validation/commerce-test-20261030t122418z-1ec58a/`。

本次审核还修复了售后期内关店与普通价调低后秒杀价格倒挂的问题；后端 Ruff、格式、mypy、compileall，前端格式、ESLint、TypeScript 和 pi adapter 类型检查均通过。现有回归没有专门覆盖上述两项修复的全部并发场景。

尚未验证真实模型调用、生产数据迁移、生产支付、跨主机故障恢复、容量及全部并发组合。本次验证不能替代这些验收。
